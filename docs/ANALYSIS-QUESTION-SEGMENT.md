# 整页拍照 → 题目框选 → 点选单题（小猿搜题式交互）可行性分析

> 目的：评估「拍一张整页试卷 → 自动把每一道题用小框标出来 → 用户点击某个框 → 针对那一题处理」的可行性。
> 状态：**仅分析，不实施。**

---

## 1. 目标交互

```
拍一整页试卷 → 后端识别 → 返回每道题的【位置框(bbox) + 文本】
        ↓
前端显示原图，每道题叠一个可点击的小框
        ↓
用户点某个框 → 选中那一题 → 触发后续（AI 解题 / 结构化入库 / 搜题）
```

关键点：**是「整页拍照、点选单题」，不是「一次只拍一道」**；也**不是**"搜题库"。

---

## 2. 当前系统已有能力（好消息：核心已在）

### 2.1 题目区域检测 —— ✅ 已实现
`backend/app/ocr/layout.py` 的 `QuestionLayoutDetector`：
- 用**投影法**把整页切分成「题目区域」，返回每题 `[x1,y1,x2,y2]`（bbox）；
- 支持单栏 / 双栏（答题卡常见）；
- **预留了 YOLO 检测钩子**（`yolo_detector` 插件点），启发式精度不够时可无缝换深度学习检测。

### 2.2 按区域 OCR —— ✅ 已实现
`ocr_pipeline.recognize`：
- 已经**按 region 切分**、对每个题目区域分别识别；
- 返回的 `blocks` 带**绝对坐标 bbox** 和文本，天然可以聚合成「每题文本」。

### 2.3 已有相关前端
- `image_crop_screen.dart`：图裁剪（可复用图片显示/交互）。
- `question_split_confirmation_screen.dart`：多题拆分确认（但当前是**文本列表**逐条确认，非"图上点选"）。

---

## 3. 差距与所需新增

| 缺口 | 说明 | 难度 |
|---|---|---|
| 后端暴露「每题 bbox + 每题文本」接口 | 检测和识别**都在内部**做了，只是 `/api/ocr/recognize` 只返回合并后的整页 `ocr_text` + 所有 blocks，**没返回"每题区域"列表**。需新增接口（或扩展 analyze）。 | 小 |
| 前端「整页图 + 可点选题框」 | 新增一个屏：显示原图 + 叠加每个 bbox 的框，点击命中检测，选中高亮。 | 中 |
| 点选后触发该题处理 | 把选中框对应的文本/裁剪图喂给现有 AI 解题/结构化/入库流程。 | 小（复用现有链路）|

---

## 4. 可行性分维度

### 4.1 技术可行性 —— ✅ 高
- 题目区域检测（bbox）**后端已有**，这是最大的坎已经跨过；
- 缺的只是「把 region 列表暴露给前端」+「前端画框点选」，都是常规开发。

### 4.2 识别精度 —— ⚠️ 中（受图片质量影响）
- **印刷体、排版规整的试卷/教辅**：启发式投影法可靠，框得准。
- **手写、乱排、无题号**：启发式可能框不准（把一道题拆成两块 / 两道题并一块）。
- 提升路径：触发预留的 **YOLO 检测**（训练/微调一个"题目区域"检测模型），精度可大幅提升，但需要标注数据 + 训练。

### 4.3 交互可行性 —— ✅ 高
- Flutter 画叠加框 + 点击命中检测是成熟做法；原图用现有 `Image` / 裁剪屏组件。

### 4.4 成本 / 工作量
- 后端接口 + 前端点选屏：**小到中**（预计几日级别）。
- 若引入 YOLO：需要模型训练/部署，工作量和算力另计（非必须，启发式先上）。

---

## 5. 方案（分阶段）

### 阶段 1：先打通「后端暴露题目区域 + 前端点选」
- 后端：新增接口（如 `POST /api/ocr/regions` 或扩展 `analyze` 返回 `regions: [{bbox, text}]`），复用 `QuestionLayoutDetector` + 按区域 OCR；
- 前端：新增「整页图 + 题目框 + 点选」屏，点某框 → 进入现有「单题分析/保存」流程；
- 交付：印刷体试卷可框选每道题并单题处理。**零新依赖、快。**

### 阶段 2（可选）：提升检测精度
- 触发 YOLO 钩子：微调一个"题目区域检测"模型，应对手写/复杂排版；
- 代价：需要标注数据 + 训练 + 部署算力。

---

## 6. 结论

**可行性：高，且比"搜题库"简单得多。**

- 题目区域检测（bbox）后端**已经实现**（`ocr/layout.py`），这是最关键的能力；
- 真正要做的只是：**① 后端把每题的 bbox + 文本暴露给前端；② 前端做"整页图 + 可点选题框"交互**，然后点选结果接现有的 AI 解题/入库流程；
- 印刷体试卷能直接框准；手写/复杂排版可用预留的 YOLO 钩子后续提升。

> 一句话：**这个需求你离"能实现"只差一层接口 + 一层前端点选交互，后端检测能力现成。**
