# 实施计划：界面视觉美化（UI Beautify）

- 状态：待评审（Plan 阶段，未实施）
- 日期：2026-11-20
- 前置依赖：`AppTokens` 设计 Token（已上线）、液态玻璃 SPEC（`SPEC-LIQUID-GLASS.md`，P0–P3 已实施、P4 已真机验收）
- 原则：**纯视觉层改造，不改任何业务逻辑、路由结构与数据流**

### 1.2 已识别的问题（本次美化的切入点）
1. **Token 覆盖不全**：features 层 20 个文件、共 **118 处硬编码 `Color(0x...)`**，
   深色模式下存在对比度失控风险，且与 Token 体系并行造成色彩不一致；
2. **玻璃浅色档观感偏弱**：已知限制「浅色主题下玻璃对比度较低」（SPEC §11），
   需在浅色档补充边缘描边/底色微调，不增加新的玻璃面；
3. **图标与文案不统一**：部分按钮仍使用大段纯文字（如「刷新」类按钮），
   与「图标优先」的偏好不符；图标尺寸存在 24px 与 20px 混用；
4. **状态页（空/加载/错误）表现力不足**：`state_views.dart` 仅基础样式，
   缺少插画/图标化的空状态引导；
5. **微交互缺失**：列表项、卡片、Tab 切换无过渡动效（玻璃转场已有，仅高档位生效）；
6. **背景图未决策**：`design/backgrounds` 已产出但未接入（涉及设计规则取舍，见 §5）。

## 2. 目标 / 非目标

### 2.1 目标
1. 全部页面取色走 `context.tokens` / `AppPalette`，消除 features 层硬编码颜色；
2. 统一图标体系（Material Icons 一套）、尺寸规范（行内 16 / 独立 20 / 导航 24）、
   文字按钮改「图标+短文案」或纯图标；
3. 提升浅色档玻璃可读性（描边 + 底色微调，不动玻璃架构）；
4. 空状态 / 加载 / 错误页图标化重设计；
5. 补充轻量微动效（150–250ms，尊重系统"减弱动态"设置）；
6. 页面间距、卡片内边距按 4px 栅格统一（s3=12 / s4=16 / s6=24）。

### 2.2 非目标（明确不做）
- 不改业务逻辑、路由、数据层；
- 不更换配色主色（indigo 体系保留）、不引入新品牌色（单视图 ≤3 品牌色）；
- 不新增玻璃面、不重构玻璃分档逻辑（沿用 SPEC-LIQUID-GLASS 结论）；
- 不做渐变按钮、玻璃拟态滥用、霓虹色、彩虹色板；
- 不改信息架构与导航结构。

## 3. 设计规则约束（全程遵守）

来源：用户全局前端设计规则，落地为本项目硬性约束：

| 类别 | 约束 |
|---|---|
| 背景 | 仅白 `#FFFFFF` / 浅灰 `#F8F9FA` / `#F3F4F6`；禁止渐变背景与按钮渐变 |
| 文字 | 主 `#111827` / 次 `#6B7280` / 弱 `#9CA3AF`（深色档用 Token 对应值） |
| 字阶 | 12/14/16/20/24/32，禁止随意字号 |
| 间距 | 4px 栅格：4/8/12/16/24/32/48/64 |
| 卡片 | 边框（1px `cardBorder`）或阴影二选一；阴影仅 shadow1/shadow2 两级；圆角 6/8px |
| 按钮 | 主=实色、次=描边/幽灵；hover/按压仅加深 10%，不变色 |
| 图标 | 单一图标集；行内 16px、独立 20px；禁止 emoji 作功能图标 |
| 色彩数 | 单视图品牌色 ≤3 |

## 4. 实施分期

### P0：Token 收口与一致性清理（基础设施，先行）
> 不改观感，先保证"改一处、全局生效"的能力。

| # | 任务 | 涉及文件 |
|---|---|---|
| 0.1 | 盘点 118 处硬编码颜色 → 逐文件映射到 Token（科目色走 `subjectColor`，难度色走 `difficultyColor`，其余按语义归类），产出映射清单 | `features/**` 20 个文件 |
| 0.2 | 补充缺失 Token：如图表系列第 4 色、角标底色等（先审计后增补，避免随手加） | `tokens.dart` |
| 0.3 | 图标尺寸统一：定义 `AppIcons` 常量（inline=16 / standalone=20 / nav=24），替换散落的 `Icon(..., size: 24)` 字面量 | 全局 |
| 0.4 | 间距审计：修掉非栅格值（13/7/23px 类），统一卡片 padding 为 s4、页面边距 s4/s6 | 高频页面 |

**验收**：`grep "Color(0x" features/` 归零（或仅剩注释/Token 定义处）；深浅色切换逐页无对比度异常。

### P1：高频页面精修（观感提升主战场）
> 按使用频率排序：错题本 > 首页 > 复习 > 详情 > 设置。

| # | 页面 | 改造点 |
|---|---|---|
| 1.1 | 错题本列表 | 卡片信息层级重排（题干预览 2 行截断、科目色条、难度/状态角标图标化）；左滑操作配色走 Token；空状态图标化 |
| 1.2 | 首页 | 统计卡网格对齐（AppStatCard 统一高度/内边距）；「拍照」主按钮图标+文案精简；额度卡（vision_quota_card，14 处硬编码）Token 化 |
| 1.3 | 复习页 | 答题卡片区块化分隔（题干/作答/解析 分组卡）；结果反馈用 success/error 软底色块 |
| 1.4 | 错题详情 | 公式区 `formulaBg` 底 + 内边距统一；知识点 chips 走 `subjectSoft` |
| 1.5 | 设置页 | 分组标题层级（textSm 次要色）；开关、选项行高统一；「玻璃外观」区与整体风格对齐 |
| 1.6 | 弹层/Toast | 统一圆角 radiusMd、内边距 s4；确认类弹层图标（删除=error 色垃圾桶等） |

### P2：状态页与微动效
| # | 任务 | 说明 |
|---|---|---|
| 2.1 | 空状态重设计 | `state_views.dart`：大图标（48px，primarySoft 底圆）+ 一句主文案 + 一句次文案 + 可选操作按钮；区分"无数据/无网络/搜索无结果"三种 |

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Token 替换改错语义色（如把 error 误换成 primary） | P0 映射清单先评审再动手；逐文件提交，便于回退 |
| 动效影响低端机性能 | 幅度小（≤250ms）、数量少；跟随系统"减弱动态"；低玻璃档设备真机复查 |
| 浅色玻璃增强与玻璃 SPEC 冲突 | 只调参数不改结构；关闭玻璃后逐页截图回归（复用 P4 流程） |
| 深色模式回归遗漏 | P2.4 强制深色逐页截图；截图清单归档 |
